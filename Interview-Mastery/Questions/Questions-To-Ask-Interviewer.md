# Questions To Ask Interviewer

## Questions

1. What are the main responsibilities of this role?
2. What kind of backend systems will be worked on?
3. What is the main technology stack used by the team?
4. Is the architecture monolithic, microservices-based, or hybrid?
5. What are the biggest technical challenges the team is solving now?
6. What are the expectations in the first 3 months?
7. How does the team handle code reviews?
8. How does the team handle deployments?
9. What CI/CD tools are used?
10. How are production issues monitored?
11. What observability tools are used?
12. How is ownership divided across services?
13. Does the team follow Agile/Scrum?
14. How much backend vs frontend work is expected?
15. Are there opportunities to work on system design and architecture?
16. How does the team handle technical debt?
17. How are performance issues handled?
18. What databases and messaging systems are used?
19. What cloud platform is used?
20. What does success look like for this role?

---

## Answers

1. What are the main responsibilities of this role?
   - **Answer:**
      - To understand whether the role is backend-heavy or full-stack
      - To check whether it aligns with strengths in Spring Boot and databases
      - Answer helps tailor follow-up questions about team structure and on-call expectations
2. What kind of backend systems will be worked on?
   - **Answer:**
      - To judge if the systems match prior professional experience
      - To evaluate whether the role involves data-intensive, high-throughput systems
      - Answer reveals scale, latency requirements, and whether the team faces performance challenges
3. What is the main technology stack used by the team?
   - **Answer:**
      - To check if Java, Spring Boot, SQL, Kafka, and AWS experience is directly applicable
      - To determine if learning new technologies will be required
      - Answer reveals framework versions and whether they are considering stack modernization
4. Is the architecture monolithic, microservices-based, or hybrid?
   - **Answer:**
      - To understand the complexity level
      - To check whether there is scope to contribute to system design decisions beyond just writing code
      - If the answer is monolith, it opens the door to ask about any planned migration to microservices and their timeline
5. What are the biggest technical challenges the team is solving now?
   - **Answer:**
      - To see if the challenges align with existing technical strengths
      - Performance optimization, data pipelines, or real-time processing
      - Answer creates an opportunity to share relevant past experience and demonstrate the ability to contribute immediately
6. What are the expectations in the first 3 months?
   - **Answer:**
      - To understand the onboarding process and what success looks like early on
      - To prioritize learning effectively
      - Answer guides follow-up questions about codebase size, documentation quality, and who would be the primary mentor during onboarding
7. How does the team handle code reviews?
   - **Answer:**
      - A good code review culture is important for growth and code quality
      - To know if reviews are thorough or just rubber-stamping
      - Answer reveals typical review turnaround time and whether performance considerations are discussed during reviews
8. How does the team handle deployments?
   - **Answer:**
      - To understand deployment frequency, automation level, and whether CI/CD is used
      - Answer reveals their deployment strategy (rolling, blue-green, canary) and how they handle failed deployments
9. What CI/CD tools are used?
   - **Answer:**
      - To see if they use Jenkins, GitHub Actions, or other tools
      - To check whether existing CI/CD experience transfers directly
      - Answer leads to follow-up questions about pipeline stages, how tests are integrated, and whether they use infrastructure as code
10. How are production issues monitored?
    - **Answer:**
       - Good observability is critical for debugging
       - To know if they have dashboards, alerts, and centralized logging
       - Answer reveals their on-call rotation, incident response process, and postmortem culture
11. What observability tools are used?
    - **Answer:**
       - To check if they use tools with which prior experience exists (CloudWatch, Grafana)
       - To determine if a new monitoring stack would need to be learned
       - Answer reveals logging aggregation, metric collection, and distributed tracing capabilities
12. How is ownership divided across services?
    - **Answer:**
       - To understand team structure
       - To check whether the role owns specific services end-to-end or works across multiple areas
       - Answer reveals team size per service and how cross-service coordination works
13. Does the team follow Agile/Scrum?
    - **Answer:**
       - To understand the work cadence
       - To check whether adapting to sprint planning, stand-ups, and retrospectives will be required
       - Answer reveals sprint length, planning process, and how technical tasks are prioritized vs feature work
14. How much backend vs frontend work is expected?
    - **Answer:**
       - To ensure the role is primarily backend
       - Backend focus is a strength and preference, rather than full-stack
       - Answer clarifies that frontend work is possible when needed but a backend-focused growth path is preferred
15. Are there opportunities to work on system design and architecture?
    - **Answer:**
       - To grow beyond implementation into design decisions
       - This aligns with the 3-5 year career goal
       - Answer reveals the team's approach to technical decision-making and whether junior engineers participate in design discussions
16. How does the team handle technical debt?
    - **Answer:**
       - To understand whether the team prioritizes code quality and refactoring
       - To check whether they focus only on feature delivery
       - Answer reveals their process for identifying and prioritizing technical debt and if there is dedicated time for refactoring
17. How are performance issues handled?
    - **Answer:**
       - Performance optimization is a key strength
       - It is important to work where this skill is valued
       - Answer reveals their performance testing process, tools used, and whether performance is a consideration in code reviews
18. What databases and messaging systems are used?
    - **Answer:**
       - To check if they use MSSQL/PostgreSQL and Kafka
       - These technologies align with prior professional experience
       - To check if different technologies are used that would need to be learned
       - Answer reveals data volume, query patterns, and whether the team has experienced performance issues at scale
19. What cloud platform is used?
    - **Answer:**
       - To see if they use AWS (with which prior experience exists) or another cloud provider
       - To check whether EC2, ALB, and IoT Core skills are relevant
       - Answer reveals their cloud migration journey, multi-region strategy, and how they manage cloud costs
20. What does success look like for this role?
    - **Answer:**
       - To understand how performance will be evaluated beyond just coding
       - Whether it is about delivery speed, quality, ownership, or business impact
       - Answer reveals promotion criteria and what the career progression path looks like for backend engineers
